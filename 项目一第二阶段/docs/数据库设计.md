# MongoDB Schema Design - 问卷系统

## 集合概览

| 集合 | 说明 |
|------|------|
| `users` | 用户账号与认证 |
| `surveys` | 问卷元数据与设置 |
| `questions` | 问卷内的题目 |
| `responses` | 用户的回答记录 |

---

## 1. 用户集合 (`users`)

```javascript
{
  _id: ObjectId,
  username: String,           // 唯一，已建索引
  email: String,              // 唯一，已建索引
  password_hash: String,      // bcrypt 加密
  role: String,               // "user" | "admin"
  is_active: Boolean,         // 默认: true
  created_at: DateTime,       // ISODate
  updated_at: DateTime        // ISODate
}
```

**索引:**
- `{ username: 1 }` (唯一)
- `{ email: 1 }` (唯一)

---

## 2. 问卷集合 (`surveys`)

```javascript
{
  _id: ObjectId,
  title: String,              // 问卷标题
  description: String,        // 问卷描述
  creator_id: ObjectId,       // 关联 users._id
  status: String,             // "draft" | "published" | "closed"
  settings: {
    allow_anonymous: Boolean, // 默认: true，允许匿名填写
    show_progress: Boolean,   // 默认: true，显示进度条
    one_per_user: Boolean,    // 默认: false，每用户限填一次
    collect_email: Boolean    // 默认: false，收集邮箱
  },
  created_at: DateTime,
  updated_at: DateTime,
  published_at: DateTime,     // 未发布时为 null
  closed_at: DateTime         // 未关闭时为 null
}
```

**索引:**
- `{ creator_id: 1 }`
- `{ status: 1 }`
- `{ created_at: -1 }`

---

## 3. 题目集合 (`questions`)

```javascript
{
  _id: ObjectId,
  survey_id: ObjectId,        // 关联 surveys._id
  title: String,              // 题目文本
  type: String,               // 见下方题目类型
  order: Integer,             // 在问卷中的显示顺序
  required: Boolean,          // 默认: false，是否必填
  options: Array,             // 选择题选项
  validation: Object,         // 类型专用校验规则
  jump_logic: Object,         // 条件跳转规则
  created_at: DateTime,
  updated_at: DateTime
}
```

**题目类型:**
| 类型 | 说明 | 需要选项 |
|------|------|----------|
| `single_choice` | 单选按钮 | 是 |
| `multiple_choice` | 多选框 | 是 |
| `dropdown` | 下拉选择 | 是 |
| `text` | 单行输入 | 否 |
| `textarea` | 多行输入 | 否 |
| `number` | 数字输入 | 否 |
| `rating` | 评分/星级 | 否 |
| `date` | 日期选择 | 否 |
| `file` | 文件上传 | 否 |

**校验示例:**
```javascript
// 文本类
{ min_length: 10, max_length: 500, pattern: "^[a-zA-Z]+$" }

// 数字类
{ min: 0, max: 100, integer_only: true }

// 评分类
{ min: 1, max: 5 }
```

**跳转逻辑示例:**
```javascript
{
  "condition": "equals",            // equals, not_equals, contains, greater_than, less_than
  "value": "选项A",                  // 对比值
  "target_question_id": ObjectId,   // 目标题目ID
  "action": "skip_to"               // skip_to, hide, show
}
```

**索引:**
- `{ survey_id: 1, order: 1 }`
- `{ survey_id: 1 }`

---

## 4. 回答集合 (`responses`)

```javascript
{
  _id: ObjectId,
  survey_id: ObjectId,        // 关联 surveys._id
  user_id: ObjectId,          // 关联 users._id (匿名时为空)
  answers: Object,            // Key: question_id(字符串), Value: 答案
  status: String,             // "in_progress" | "submitted"
  started_at: DateTime,
  submitted_at: DateTime,     // 进行中时为 null
  ip_address: String,
  user_agent: String
}
```

**各题型答案格式:**
```javascript
{
  "question_id_1": "选项A",                    // single_choice
  "question_id_2": ["选项A", "选项C"],          // multiple_choice
  "question_id_3": "用户输入的文本",            // text, textarea
  "question_id_4": 42,                         // number
  "question_id_5": 4,                          // rating
  "question_id_6": "2024-01-15",               // date (ISO字符串)
  "question_id_7": "file_hash_or_url"          // file
}
```

**索引:**
- `{ survey_id: 1, user_id: 1 }` (复合，用于 one_per_user 检查)
- `{ survey_id: 1, status: 1 }`
- `{ submitted_at: -1 }`
- `{ user_id: 1 }`

## 关系图

```
users (1) ──────< (N) surveys
surveys (1) ────< (N) questions
surveys (1) ────< (N) responses
users (1) ──────< (N) responses
questions (1) ──< (N) responses (通过 answers 对象)
```

## 常用查询

### 获取问卷及题目
```javascript
// 问卷
db.surveys.findOne({ _id: ObjectId("...") })

// 按顺序获取题目
db.questions.find({ survey_id: ObjectId("...") }).sort({ order: 1 })
```

### 获取用户的问卷列表
```javascript
db.surveys.find({ creator_id: ObjectId("...") }).sort({ created_at: -1 })
```

### 获取问卷的已提交回答
```javascript
db.responses.find({ 
  survey_id: ObjectId("..."), 
  status: "submitted" 
}).sort({ submitted_at: -1 })
```

### 检查用户是否已作答
```javascript
db.responses.findOne({ 
  survey_id: ObjectId("..."), 
  user_id: ObjectId("...") 
})
```

### 问卷统计
```javascript
db.responses.aggregate([
  { $match: { survey_id: ObjectId("..."), status: "submitted" } },
  { $group: { _id: null, total: { $sum: 1 } } }
])
```

## 设计说明（Design Rationale）

### 1. 为什么这样设计（四个集合分离）

| 集合 | 职责边界 | 设计依据 |
|------|---------|---------|
| `users` | 仅存储用户账号与认证信息 | 用户是独立身份实体，与问卷/回答的生命周期解耦，支持复用（一个用户可创建多份问卷、提交多份回答） |
| `surveys` | 问卷元数据与全局设置 | 问卷是资源容器，标题/描述/状态/设置随问卷整体变更，不随单题或单回答变化 |
| `questions` | 问卷内的题目定义 | 题目属于某一问卷，但题目结构（类型/选项/校验/跳转）与回答数据不同生命周期，分离便于独立管理题目顺序、修改题目而不影响已提交回答 |
| `responses` | 用户的提交答案 | 回答是提交时的快照，包含大量动态字段（answers 对象随题型而异），与题目定义解耦，避免修改题目时需要迁移历史回答 |

遵循**“勿将所有数据存在一个集合”**原则：将用户、问卷、题目、回答四个领域实体拆分为四个独立集合，避免单集合膨胀和字段冲突，便于独立索引、查询和扩展。

### 2. 为什么不用关系数据库结构

问卷系统的核心特征是**数据结构不固定、动态扩展强**：

- **题型多样且答案格式各异**：单选题答案是字符串，多选题是数组，文本题是长字符串，评分题是数字，日期题是字符串，文件题是 URL。关系数据库需要为每种题型设计独立表，或使用 EAV（Entity-Attribute-Value）模型导致连接查询复杂。
- **问卷结构动态**：创建者可自定义题目数量、类型、选项、跳转逻辑，这属于典型的半结构化数据，关系数据库的固定 Schema 难以灵活适配。
- **跳转逻辑动态**：条件/动作/目标题目运行时才确定，不适合预先设计固定外键关系。
- **回答数据读多写少**：统计场景下主要按 `survey_id` 聚合，不需要复杂的多表连接，文档模型天然适合聚合查询。

关系数据库在这些场景下需要频繁 `ALTER TABLE` 或大量 JOIN，开发和维护成本高。

### 3. 为什么适合 MongoDB

| MongoDB 特性 | 在问卷系统中的体现 |
|-------------|------------------|
| **无固定 Schema** | `questions.validation`、`questions.jump_logic`、`responses.answers` 均为动态嵌套文档，不同题型字段完全不同，无需预定义列 |
| **嵌入式文档** | 问卷设置 `settings` 嵌入在 `surveys` 文档中，读取问卷时一次即可获得全部元数据，无需 JOIN |
| **数组原生支持** | 选择题选项 `options` 直接存为数组，多选题答案也直接存为数组，查询简单 |
| **聚合框架强大** | 统计页面的每日趋势、选项分布、数值统计均可通过 `$match`/`$group` 直接在 MongoDB 端完成，无需在应用层循环计算 |
| **水平扩展** | 回答数据随时间线性增长，MongoDB 支持分片，适合高并发写入和大规模读取 |

### 4. 遵循的设计建议

**建议一：勿将所有数据存在一个集合**
已拆分为 `users`、`surveys`、`questions`、`responses` 四个集合，每个集合只存储其领域内的字段，避免单集合字段过多和查询混乱。

**建议二：谨慎使用冗余设计**
- 目前仅在 `responses` 中保留 `user_id` 的字符串副本（用于匿名/登录双模式兼容），其余通过 `ObjectId` 引用关联，避免数据冗余导致一致性问题。
- 题目标题等元数据不冗余存入回答集合，统计时通过 `survey_id` 关联 `questions` 集合获取。

**建议三：勿把逻辑写死在代码**
- 题目类型、校验规则、跳转逻辑全部存储在 `questions.validation`、`questions.jump_logic` 字段中，由服务层动态读取执行。

## 第二阶段扩展：题目库与题目版本

第二阶段在保留原四个集合的基础上新增四个集合。`questions` 仍然保存“问卷内题目快照”，原有统计、填写和导出逻辑不需要改变；新增字段只用于把快照关联回题目库。

### 5. 题目家族集合 (`question_families`)

```javascript
{
  _id: ObjectId,
  owner_id: ObjectId,              // 题目作者
  title: String,                   // 当前最新版本标题
  description: String,
  latest_version_id: ObjectId,     // 指向 question_versions._id
  version_count: Integer,          // 已创建版本数
  is_public: Boolean,              // 是否公开给所有用户
  shared_with: [ObjectId],         // 被共享用户 ID 列表
  derived_from_family_id: ObjectId,// 派生来源（可选）
  derived_from_version_id: ObjectId,
  archived: Boolean,
  created_at: DateTime,
  updated_at: DateTime
}
```

**索引:** `{ owner_id: 1 }`、`{ shared_with: 1 }`、`{ is_public: 1 }`

### 6. 题目版本集合 (`question_versions`)

```javascript
{
  _id: ObjectId,
  family_id: ObjectId,             // 关联 question_families._id
  version_number: Integer,         // 1, 2, 3...
  title: String,
  type: String,
  required: Boolean,
  options: Array,
  validation: Object,
  jump_logic: Object,
  parent_version_id: ObjectId,     // 从哪个版本修改而来
  restored_from_version_id: ObjectId, // 恢复操作的目标版本
  created_by: ObjectId,
  change_note: String,
  created_at: DateTime
}
```

版本文档只追加、不更新。恢复旧版本时会创建一个新版本，并通过 `restored_from_version_id` 记录来源，从而保证完整历史。

**索引:** `{ family_id: 1, version_number: -1 }`（唯一）、`{ parent_version_id: 1 }`

### 7. 题库集合 (`question_banks`)

```javascript
{
  _id: ObjectId,
  owner_id: ObjectId,
  name: String,
  description: String,
  is_default: Boolean,
  created_at: DateTime,
  updated_at: DateTime
}
```

**索引:** `{ owner_id: 1, name: 1 }`（唯一）

### 8. 题库条目集合 (`question_bank_entries`)

```javascript
{
  _id: ObjectId,
  bank_id: ObjectId,               // 关联 question_banks._id
  family_id: ObjectId,             // 关联 question_families._id
  added_by: ObjectId,
  added_at: DateTime
}
```

**索引:** `{ bank_id: 1, family_id: 1 }`（唯一）

### 9. `questions` 集合新增字段

```javascript
{
  bank_family_id: ObjectId,        // 来源题目家族，用于“使用情况”和跨问卷统计
  bank_question_id: ObjectId,      // 选中时的具体版本
  bank_version: Integer,           // 版本号，便于页面展示
  // 原有字段保持不变：survey_id/title/type/order/required/options/validation/jump_logic
}
```

**索引:** `{ bank_family_id: 1 }`、`{ bank_question_id: 1 }`

### 10. 一致性规则

1. 从题库选题时，服务层把版本内容复制到 `questions`，所以之后修改题库题目不会改变旧问卷。
2. `questions` 一旦所属问卷发布过（`published_at` 非空），题目增删改、排序全部拒绝；撤回后也不解锁，需要“复制为新版本问卷”继续编辑。
3. 修改题库题目只向 `question_versions` 追加文档，不更新旧版本；不同问卷可以分别引用不同 `bank_question_id`。
4. 跨问卷统计按 `bank_family_id` 汇总，再根据每份问卷题目的 `_id` 从 `responses.answers` 中读取回答；统计权限按题目作者/共享者区分。

- 新增题型或新增跳转条件时，只需在数据层插入新文档，无需修改 Python 代码并重新部署。
